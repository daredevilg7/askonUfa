# Мини-PDM «Состав изделия»

Десктопное приложение для импорта эмуляции CAD-документов, хранения версий и состава изделия, расчёта массы и сводной спецификации. Реализация выполнена по приложенному заданию «.NET: Мини-PDM». Интерфейс, сообщения и документация — на русском языке.

## Быстрый запуск

Требуется **.NET SDK 8** и поддерживаемая Avalonia настольная система (Windows, macOS или Linux). Сервер базы данных и Docker не нужны.

Из корня репозитория:

```bash
dotnet restore
dotnet build
dotnet test
dotnet run --project src/MiniPdm.Desktop
```

При первом запуске приложение создаёт базу SQLite в каталоге пользовательских данных: `MiniPdm/mini-pdm.db`. Другой путь задаётся переменной `MINIPDM_DB`:

```bash
MINIPDM_DB=./mini-pdm.db dotnet run --project src/MiniPdm.Desktop
```

Для проверки откройте в приложении папку `sample-data/cad-export`. Выберите в списке «Редуктор цилиндрический Ц2-160», затем нажмите «Рассчитать массу» и «Сводная спецификация». Результат импорта показан на вкладке «Отчёт импорта». Для проверки версионирования утвердите текущие версии объектов и импортируйте `sample-data/cad-export-v2`. Интеграционный тест выполняет эту последовательность автоматически.

## Технологии и структура

- **.NET 8, C#** — единая платформа для логики, доступа к данным и интерфейса.
- **Avalonia 11 + CommunityToolkit.Mvvm** — кроссплатформенный настольный интерфейс и команды MVVM. В `MainWindow.axaml.cs` находится только загрузка XAML.
- **SQLite + Dapper** — реляционное хранение и явный SQL. SQLite разрешён заданием и позволяет проверить весь сценарий без внешнего сервера. PostgreSQL лучше соответствует рабочему стеку компании, но потребовал бы запуска отдельной СУБД и усложнил бы самодостаточную проверку.
- **xUnit** — модульные и интеграционные тесты; они создают временные базы и не требуют Docker.

| Проект | Ответственность |
| --- | --- |
| `src/MiniPdm.Domain` | Проверка обозначения и допустимых переходов состояния |
| `src/MiniPdm.Application` | CAD-модель, интерфейсы, проверка пакета, сценарий импорта, расчёты |
| `src/MiniPdm.Infrastructure` | JSON-адаптер, схема и запросы SQLite, транзакционное хранение |
| `src/MiniPdm.Desktop` | Avalonia-представление, ViewModel и единственное место композиции зависимостей |
| `tests/MiniPdm.Tests` | Правила, импорт с подменным CAD-reader, БД, расчёты и данные задания |

Зависимости направлены от интерфейса и инфраструктуры к Application, а от Application к Domain. `MainViewModel` получает `IProductCatalog`, прикладной `ImportService` и абстракцию выбора папки через конструктор. Конкретные реализации собираются в `App.axaml.cs`.

## Схема и правила версий

Схема хранится в [скрипте 001_initial.sql](src/MiniPdm.Infrastructure/Database/001_initial.sql). Он встроен в сборку и идемпотентно выполняется при запуске. Таблицы:

- `pdm_object`: тип, уникальное обозначение для сборок/деталей или уникальное имя стандартного изделия, текущая версия;
- `object_version`: номер, состояние, материал и масса;
- `bom_link`: версия родительской сборки, **дочерний объект** и положительное количество.

Частичные уникальные индексы и внешние ключи поддерживают ограничения схемы. `current_version_id` обновляется в той же транзакции, что и создание или отмена версии. При отмене текущей выбирается версия с наибольшим номером среди неаннулированных; если такой нет, указатель становится `NULL`. Следующий импорт существующего объекта без текущей версии создаёт версию `max(version_no) + 1` в состоянии «В работе».

Разрешены только переходы «В работе» → «Утверждено»/«Аннулировано» и «Утверждено» → «Аннулировано». Запрет проверяется в хранилище по правилу Domain внутри транзакции, даже если кнопка в интерфейсе недоступна. Изменение утверждённой версии создаёт новую рабочую версию; старые атрибуты и связи не перезаписываются. Неизменившийся документ версию не меняет. Связь состава указывает на объект, поэтому неизменившаяся родительская версия использует **новую текущую версию** дочернего объекта.

SQLite не имеет отдельного точного десятичного типа: масса хранится в `TEXT` в инвариантной десятичной записи и преобразуется в `decimal` для сравнения и расчётов. Это исключает погрешность двоичного `REAL`.

## Импорт CAD

`ICadDocumentReader` возвращает результаты чтения каждого документа. Его реализация перечисляет файлы, читает UTF-8 и разбирает JSON; прикладной сервис не обращается к файловой системе и JSON. Сигнатура отличается от иллюстрации в PDF, чтобы повреждённый файл попадал в отчёт и не прерывал остальные. Идентификатор — имя файла на диске; несовпадение поля `fileName` отклоняется.

Порядок обработки:

1. Чтение всех `.a3d` и `.m3d` и запись ошибок чтения пофайлово.
2. Проверка типа, версии формата, кириллического обозначения, материала, массы, компонентов и положительных количеств. Отсутствующая масса обычной детали — предупреждение с сохранением объекта.
3. Отклонение **всех** файлов с одинаковым обозначением в пакете; также всех стандартных изделий с одинаковым именем.
4. Поиск циклов по стеку обхода и распространение отклонения на зависимые сборки до неподвижной точки.
5. Сохранение всех принятых документов **одной транзакцией**. Ошибка записи откатывает весь принятый набор. Повторные строки одного компонента суммируются; переполнение количества отклоняется до записи.

Повторный импорт сравнивает свойства и нормализованные связи, без зависимости от порядка строк JSON. Наименование находится на уровне объекта и считается метаданными: изменение только имени сборки/детали не создаёт новую версию. Переименование стандартного изделия создаёт новый объект, поскольку имя — его идентификатор.

## Дерево, масса и спецификация

[Запрос дерева](src/MiniPdm.Infrastructure/TreeSql.cs) — **один рекурсивный CTE**. Он подставляет `current_version_id` каждого дочернего объекта, умножает количества вдоль пути и защищён от циклов в повреждённой базе. Циклические ссылки в новых данных дополнительно отклоняются до сохранения. Превышение диапазона количества вызывает ошибку расчёта, а не неверное число.

Масса сборки — сумма масс листовых деталей и стандартных изделий с учётом произведения количеств по каждому пути. Если масса хотя бы одного листа не указана, итог отсутствует, а интерфейс перечисляет проблемные компоненты. В сводной спецификации одинаковые объекты агрегируются по ID, включая повторения на разных уровнях; строка без массы остаётся и показывает пустую массу. Версии «Аннулировано» без текущей замены не участвуют в расчёте.

## Проверка на приложенных данных

Оба набора содержат по **45** документов. Проверены все `.a3d` и `.m3d` в архиве и интеграционным тестом реального импорта.

### Базовый `cad-export`

**34** строки «Принято», **1** «Предупреждение», **10** «Ошибка». Итого сохранено **35** объектов, из них один с предупреждением.

| Файл | Причина |
| --- | --- |
| `Втулка распорная.m3d` | Первая буква обозначения — латинская `P` |
| `Кольцо распорное.m3d` | В средней группе обозначения пять цифр вместо шести |
| `Отдушина.m3d` | Повреждённый JSON |
| `Пробка сливная в сборе.a3d` | Нулевое количество компонента |
| `Привод масляного насоса.a3d` | Отсутствует файл `Насос шестерённый НШ-10.m3d` |
| `Шайба стопорная.m3d`, `Шайба упорная.m3d` | Совпадающее обозначение; отклонены оба файла |
| `Рычаг переключения.a3d`, `Тяга переключения.a3d` | Цикл состава; отклонены оба участника |
| `Механизм переключения.a3d` | Зависит от отклонённого рычага |

Предупреждение: `Прокладка маслоуказателя.m3d` не содержит массы и сохраняется. Для сборки `Маслоуказатель в сборе.a3d` итоговая масса недоступна с указанием этой прокладки.

Корневая сборка `Редуктор цилиндрический Ц2-160.a3d`: **98,8040 кг**, **25** различных листовых позиций, **118** изделий после развёртывания количеств. Для `Прокладка регулировочная.m3d` суммарное количество — **12**.

### После `cad-export-v2`

Входной отчёт снова содержит 34 принятых без предупреждения, 1 предупреждение и 10 ошибок. После утверждения всех 35 исходных версий **33** принятых документа не изменились, у **2** созданы версии № 2 «В работе»:

- `Колесо зубчатое.m3d`: масса с 5,86 до 5,92 кг;
- `Крышка подшипника в сборе.a3d`: число регулировочных прокладок с 3 до 4.

Предыдущие версии № 1 остаются утверждёнными. Корневая сборка остаётся на версии № 1, но её масса становится **98,8800 кг** (изменение **+0,0760 кг**). Регулировочных прокладок становится **16**, суммарное развёрнутое количество листовых изделий — **122**.

## Ограничения и дальнейшие шаги

Обязательные сценарии реализованы. Из дополнительных возможностей не добавлены индикатор прогресса и отмена импорта, вторая СУБД, экспорт CSV/XLSX, сравнение версий и структурированное логирование. Их можно добавить отдельными адаптерами и командами без изменения Domain. Дерево читается целиком одним CTE; ленивой подгрузки нет. Поиск намеренно фильтрует небольшую коллекцию объектов в C# для корректной нечувствительности к регистру кириллицы; для большой базы потребуется индексируемый поиск. Скрипт схемы идемпотентен, но для будущих изменений структуры понадобится журнал версий миграций.
